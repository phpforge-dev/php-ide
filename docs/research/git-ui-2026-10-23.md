# Git — reprodução visual de 23/10/2026

## Referência documental

Pedido do usuário: copiar a UI do PhpStorm. A imagem de Git Log da [documentação oficial 2026.2](https://www.jetbrains.com/help/phpstorm/log-tab.html) foi examinada no navegador. Observados: toolbar vertical estreita, árvore Local/Remote, busca e filtros acima da tabela, grafo e referências junto às mensagens, arquivos acima dos detalhes à direita. Não houve observação nativa do PhpStorm nesta sessão nem medição pixel a pixel. As observações anteriores de Commit permanecem em [phpstorm-git.md](phpstorm-git.md).

## Implementação própria

- Log mantém dock inferior e passa a usar a composição da referência: toolbar vertical, branches agrupadas com busca e opção de ocultar, tabela compacta de 26 px, referências e grafo, painel de arquivos e detalhes separados.
- Busca textual, filtro de branch, autor e data funcionam sobre o conjunto carregado. Branch consulta o backend; autor/data filtram os até 100 commits carregados. Filtros não anunciam busca completa no repositório.
- Grafo usa pais reais retornados por Git CLI com ordem topológica. Apenas arestas entre commits visíveis são desenhadas; filtros podem interromper linhas, sem inventar relação entre commits. Referências vêm de `%D`.
- Commit lateral tem título estável, toolbar compacta com tooltips, grupos recolhíveis e mensagem/botão na base. Erro continua explícito na área de feedback, sem substituir o título da ferramenta por “Git unavailable”. Staging/revisão mantidos.
- Temas usam tokens existentes; nenhum asset ou código proprietário extraído. Novos ícones da toolbar são SVGs próprios.

## Limites

Equivalência visual em desenvolvimento. A composição aproxima a referência pública; não é uma cópia pixel a pixel certificada. Sem changelists do PhpStorm, favoritos/tags na árvore, filtros por caminho, paginação, menus completos ou redimensionamento das divisões internas. Layout reduzido esconde autor/data abaixo de 1100 px. O requisito de abrir a raiz Git do projeto permanece; este recorte é visual, não muda o mapeamento de repositórios. Sem promoção de TOOL-GIT-001 para compatibilidade validada.

## Painel Commit — referência enviada pelo usuário

Duas capturas fornecidas pelo usuário mostram o Commit do PhpStorm e o painel anterior da nossa IDE. Evidência visual fornecida, não observação interativa nesta sessão. Reproduzidos: título Commit estável, toolbar só com ícones, grupos com checkbox/contagem e seleção azul, arquivo separado da pasta, área livre flexível, divisor, Amend, caixa de mensagem de 170 px e botões Commit / Commit and Push na base. Busca fica recolhida até acionada pela toolbar; operações e conta deixam de ocupar linhas de texto permanentes. Painel com largura mínima visual de 360 px, limitado pelo viewport. Não reproduzidos os ícones de ações ainda sem suporte.

Checkboxes operam sobre staging explícito, com estado intermediário quando index e disco têm mudanças. Não são changelists do PhpStorm. Seleção de arquivo continua abrindo diff. Mutações preservam validação por token e feedback de erro; foco do checkbox é restaurado após atualização. Amend lê a mensagem completa, restaura o rascunho ao desmarcar e exige revisão explícita; backend rejeita HEAD/index obsoletos e operação em andamento. Commit and Push cria o commit revisado e abre a confirmação de push existente, sem force push automático.

Testes Rust: 63 aprovados, cinco opt-in ignorados. Novo caso comprova amend com mensagem/corpo, preservação de alterações não preparadas, substituição em vez de novo commit, conteúdo preparado e rejeição de revisão obsoleta/HEAD ausente. Typecheck e locales aprovados. Captura própria: `.artifacts/git-commit-reference-match.png`. Runner de UI atualizado: 18 grupos aprovados, incluindo stage/unstage por checkbox, restauração do rascunho de Amend, expandir/recolher grupos e Commit and Push abrindo a revisão de push. Build release concluído e assinado localmente em `src-tauri/target/release/bundle/macos/PHP IDE.app`. O primeiro smoke desta etapa em desenvolvimento passou Git UI, mas registrou falhas de estado após edição de fonte com Vite ativo; não conta como suíte aprovada. A reexecução no pacote sem HMR avançou até Docker/Compose e atingiu o timeout global de 180 segundos, sem relatório final; portanto não comprova aprovação da suíte nativa completa. Os 18 grupos UI simulados e 63 testes Rust continuam como evidência específica aprovada.
